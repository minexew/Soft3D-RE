Description of the file "Basefont.sbn".

Font file. has the following structure:
The beginning of the file
0F 00 00 00 - ?unknown_value
40 00 00 00 - number of characters in file (64 in DEC)

Character data:
07 00 00 00 - character width
0F 00 00 00 - character height
10 00 00 00 - how long does a symbol take (16 byte’s in DEC)
__DATA__    - symbol
---------------------------------------
---------------------------------------
When modifying a font file, you should rely on data from the parser.sbn files: 
...
if val == 3:
    c = " "
elif val >= 4 and val < 30:
    c = chr(ord("a") + (val - 4))
elif val >= 30 and val < 56:
    c = chr(ord("A") + (val - 30))
elif val >= 56 and val < 66:
    c = chr(ord("0") + (val - 56))
elif val == 67: c = "..."
elif val == 69: c = "?"
elif val == 70: c = "'"
elif val == 71: c = "!"
...

The English alphabet takes up 26 letters, which is clearly visible in the parser code.
* 4 to 30 lowercase letters;
* from 30 to 56 - uppercase;
* digits 56 to 66.
Next are special characters.
!all values ​​from the code are written in DEC!

S2D SDK correlation:
The S2D Font accessors use the same 12-byte glyph records (width at +0, height at +4, data at +8) and the same character-code mapping. Soft3D adds a 0x14-byte s3dBase/s3dIO prefix to the Font and StringManager layouts. The constructor at 0x000de9ec is StringManager_Ctor, not BaseFont_ctor; Font_Ctor is at 0x000dc7f8. See s2dsdk_correlation.md for offsets and accessor addresses.

Symbian 3rd parser and rendering recovery:

Base font (`basefont.sbn`):
    u32 maxHeight
    u32 baseGlyphCount
    Glyph baseGlyphs[baseGlyphCount]

Additional local font and strings (`system.sbn`):
    u32 localGlyphCount
    Glyph localGlyphs[localGlyphCount]
    u32 stringCount
    String strings[stringCount]

Glyph:
    u32 width
    u32 height
    u32 dataByteCount
    u8 data[dataByteCount]

String:
    u32 codeCount
    u32 codes[codeCount]

The reference Chinese archive has 64 base glyphs in basefont.sbn (1764 bytes), and 18 local glyphs plus 581 strings in system.sbn. ParseBaseFontData is 0x000dd5ac; ParseSbnFontData is 0x000dd370. LoadBaseFontResource is 0x000defdc and LoadSbnFontResource is 0x000df514. After each glyph, the original cursor advances by dataByteCount & ~3, not by a rounded-up size. All glyph sizes in these files are already multiples of four.

For languages other than 2, ParseBaseFontData adds 2 to maxHeight. Character code 3 is blank: its height comes from base glyph 0, but its width comes from base glyph 3 (the record at base + 0x24), not from glyph 0. Codes below 3 have zero metrics. Codes 4 and above select base glyph code - 4, then local glyph code - 4 - baseGlyphCount.

VisString control codes are 0 = newline, 1 = set color followed by a 0x00RRGGBB word, 2 = restore color, and 3 = blank. ARM VisString_AppendText maps a-z to 4..29, A-Z to 30..55, and 0-9 to 56..65. '-' maps to 66; other characters below '-' map to blank; and characters from '.' upward map to 67. This is simpler than the punctuation mapping in the older parser notes above.

StringManager_DrawChar (0x000e11a4) treats glyph data as packed row-major bits, least-significant bit first within each byte. A set bit writes color | 0x7fff0000 into the 32-bit RGB565/depth framebuffer, with clipping against the configured target. Point anchors use bit 1 for right, bit 2 for horizontal center, bit 5 for bottom, and bit 6 for vertical center. The portable implementation is in Reversed_Game/src/soft3d/Font.* and is tested against both real SBN resources by tests/test_font.cpp.

The initial handedness labels are STX palette images, not SBN text. See sdt_format.md for their state-table records.
