# AGENTS.md — notes for AI coding agents

## Project overview

Soft3D-RE is a reverse-engineering and preservation project for the **Soft3D** game engine (C++, some builds include RTTI), best known from the mobile game **7 Days: Salvation**. The same engine was also used by 天地道 (Hellstriker II) and 斗地主 on the Gemei A330. Target platforms of the original game: Dingoo A320, Gemei A330, Symbian S60 (v1/v2/v3), and Win32.

The repository is *not* a single buildable application. It is a research collection:

- archived original game releases (binaries),
- reverse-engineering notes and format documentation,
- small standalone analysis/conversion tools written in Python 3 and C#,
- leaked original material (script sources, docs, tools).

Upstream: `git@github.com:minexew/Soft3D-RE.git`. The README's file-format table (S3DTEX, SBN, SBP, SAU, WAR, STX, SOJ, SST, SPL, SDT, SAI, S3DSTY) is the canonical index of what is understood; keep it updated when a format's status changes (legend: ✔️ well-understood, 🔧 mostly understood, ❌ unknown).

### Tools/ in detail

- **Python 3 scripts** (single-file, run directly, no packaging): `decodesau.py` (SAU/WAR AMI ADPCM → WAV, with WAR nibble-order conversion), `nibbleswap.py` (IMA ADPCM → SAU nibble swap), `extractspk.py` (SPK archive extractor), `s3dtex.py` / `stx.py` (texture converters, require **Pillow**), `sbn.py` (font), `sbp.py` / `parse-sbp.py` (Quake-2-BSP-derived map format), `sojconv.py` (SOJ↔OBJ/MTL and SAI-sampled OBJ frame series), `sis_unpacker.py` (Symbian SIS), plus small helpers (`app_get_date.py`, `convert-inplace.py`, `hex_splitter.py`). `test_sojconv.py` is its standalone unittest suite, including real archive resources. `test_s3dtex.py` validates all 173 vendored S3DTEX samples plus synthetic palette/color-key/malformed variants.
- `BspViewer/` — C# .NET Framework 4.5 / OpenTK 3.0.0 3D map viewer (Visual Studio `.csproj` + `packages.config`). Usage in `Tools/BspViewer/README.md`.
- `SimpleScriptDecompiler/` — C# .NET Framework 4.5 console decompiler for SST "simple script" files; supports `Win32` and `Mobile` script variants (`Script/Win32`, `Script/Mobile`, `Decompiler/*`).

## Build and test commands

There is no repository-wide build or CI. Build/run each research tool independently; `Reversed_Game` has its own CMake build and CTest suite:

- Reconstructed game: `cmake -S Reversed_Game -B Reversed_Game/build`, `cmake --build Reversed_Game/build --parallel`, and `ctest --test-dir Reversed_Game/build --output-on-failure`. The tests exercise synthetic SPK archives and resource files, cache lifecycle and directory normalization, real SAU/SOJ/SAI/STX/SBN/SDT resources from `Reversed_Game/src/resources/res.spk`, FilePak streaming and memory-resident modes, standalone IO writes/reopen/narrow-path/wide formatting, stream sentinel/endian/file-flush behavior, RAM diagnostics, unit and script archive-state round trips, both decoder nibble orders, both logging backends, `VID_impl` lifecycle/error handling and exact dummy-presented pixels, engine queue ordering/capacity, portrait/landscape RGB565-to-XRGB presentation, complete engine-to-dummy-video frames, SOJ rasterization, real animated SOJ/SAI Object rendering, all four renderable effects and offscreen span clipping, real and synthetic SBP loading with incremental progress/models/entities/malformed chunks, BSP/PVS rendering, lightmaps, S3DSTY wrapping, real and synthetic SPL evaluation/camera timing, moving menu-backdrop frames, and exact dummy-presented frame hashes, packed material names, SAI interpolation and wrapping, real font drawing, text wrapping/anchoring/ranges, all seven generic and concrete dialog classes, startup/handedness/sound/main-menu flow, options/load/help/about/GameUI navigation, configuration round trips, 923 real SDT keys, interpolation boundaries, every ScreenBlitter mode, clipping/scaling, secondary textures, both initial handedness selections through engine input, 23-key transitions and repeat counts, Symbian/SDL key translation, deterministic 17 FPS timing, lifecycle, default-off/opt-in FPS text, exact 16-voice mixing and positional/fade behavior, threaded audio lifecycle, real SAU/UI-sound playback and final-word decoder boundaries, real and synthetic SST parsing plus every implemented VM opcode/reference/task/call/suspension path, generic messaging/unit-manager/state/physics behavior, synthetic and real BSP collision, and SDL dummy-video/audio app smoke tests. The decoder defaults to SAU; use `-DSOFT3D_AUDIO_REVERSE_NIBBLE_ORDER=ON` for WAR's high-nibble-first variant. SPK defaults to the Chinese 64-byte-path layout; configure a separate directory with `-DSOFT3D_SPK_ENGLISH_LAYOUT=ON` for English 32-byte-path archives, and test that variant independently because real-archive tests require the Chinese fixture. Logging defaults to release-like `NULL`; use `-DSOFT3D_LOG_BACKEND=STDIO` to enable UTF-16LE `log.log` output, and test that variant in a separate build directory. Sine/tangent lookups use the original 2049-entry tables by default; `-DSOFT3D_TRIG_USE_MATH=ON` selects host trigonometry in a separate build. Stage 3 adds every game-camera mode, binding/freeze/interpolation, SPL completion/projection, shake, nested camera restoration, real camera/light trigger consumers, exact door transition frames, environment/listener scheduling, ending-title hashes, and game-over restart. Tests also cover standalone TGA loading, file-based SBN loading, viewport propagation, path editing, and direct dialog blits/accessors.
- SDL3 app: run `Reversed_Game/build/seven_days` after building. It requires SDL3 (`find_package(SDL3 CONFIG)`), runs `GameEngine::RunFrame` with a 320×240 CPU framebuffer, an XRGB8888 SDL streaming texture, and the 16 kHz mono software-mixer output through `SDL_AudioStream`, and falls back to SDL's software renderer. The default `--orientation auto` shows the initial handedness dialog in portrait with direct phone-key directions, then switches to landscape and counter-rotates the current handedness output and arrows/WASD so gameplay stays upright and screen-relative. Explicit `--orientation landscape` and `--orientation portrait` force one presentation throughout. Other options: `--renderer auto|software|NAME`, `--scale 1..4`, `--frames N`, `--resources PATH`, `--no-audio`, `--show-fps` (explicit restoration of the dormant base FPS text), and `--new-game` for immediate day-1 startup and scene-state reporting. Controls are arrows/WASD, Space/Enter, and Escape. Disable the app target with `-DSOFT3D_BUILD_APP=OFF`; the core library and dummy video/audio backend tests do not require SDL.
- Headless app validation: Xvfb, xdotool, xwd, and ImageMagick are available. Run the app with `DISPLAY` pointing to Xvfb, use `xdotool windowfocus` (there is no window manager), capture with `xwd`, and convert with `magick`. SDL's `dummy` video/audio drivers are useful for nonvisual smoke tests.
- Python tools: `python3 Tools/<script>.py ...` (Python 3; only `s3dtex.py` and `stx.py` need Pillow — there is no `requirements.txt`). Run the SOJ/OBJ/SAI converter suite with `python3 Tools/test_sojconv.py -v` and the S3DTEX suite with `python3 Tools/test_s3dtex.py -v` from the repository root.
- C# tools: open the `.csproj` in Visual Studio (targets .NET Framework v4.5, NuGet restore via `packages.config`, OpenTK 3.0.0). `msbuild`/`dotnet build` may work on Linux with .NET Framework reference assemblies, but Windows/VS is the intended toolchain.
- Extractor: `qmake` + Qt Widgets, built with Qt Creator (`Extractor.pro`); generated Makefiles are checked in.

For research tools without automated tests, verification means running the tool on sample assets and comparing output against known-good results or original game behavior.

## Code style and conventions

- Documentation and code comments are in **English**; leaked sources/docs are Chinese (GBK). Keep new docs in English.
- Python style used across `Tools/`: `argparse` CLI (`description=`, positional `type=Path` args), `struct` with little-endian format strings (`"<..."`) for all binary I/O, `pathlib.Path`, plain functions + `print` output, no tests. Match the existing script you are editing rather than introducing frameworks.
- Binary formats are little-endian; SBP maps derive from the Quake 2 BSP format. 3D coordinates: -Z forward, Y up (see comment in `sojconv.py`).
- The Python scripts deliberately target the raw binary formats; when a format variant differs per platform (e.g. SBN 32-bit on GA330 vs 7-bit on Win32, SPK `--variant eng|chi`), handle the variant explicitly like the existing code does.
- Keep the README format table in sync when improving a format parser.

## Security and handling considerations

- `Releases/` and `Leaked_*` contain proprietary third-party binaries and documents preserved for research. Do not execute the Windows executables on sensitive systems, do not redistribute modified copies, and do not delete or "deduplicate" them.
- Do not commit large extracted game assets; `.gitignore` excludes `__pycache__/`, `Thumbs.db`, and `Reversed_Game/build/` — check `git status` before committing and leave generated outputs (extracted resources, decoded WAVs, build directories) out.

## Notes for Ghidra MCP Usage

- Ghidra will likely be run with inline scripting disabled, so for bulk changes and batch operations prefer running Python scripts that are directly calling into MCP server via REST API over using inline script tool.
- If you end up inexplicably calling a wrong Ghidra tool instead of one you've meant to call via MCP more than 3 times in a row and feel stuck - switch over to directly calling MCP server's REST API from Python scripts.
